# Release Checklist

## 1. Freeze Release Inputs

- Confirm target environment file or secret set:
  - `DATABASE_URL`
  - auth/session settings
  - storage settings (`local` or `s3`)
  - upload policy envs
- Confirm `AUTH_ALLOWED_ORIGINS` contains the real web origin used in release verification and production.
- Confirm deployment mode:
  - `STORAGE_PROVIDER=local` or `STORAGE_PROVIDER=s3`
  - expected public file URL
- Confirm seeded local credentials are not exposed in production.
- Confirm current release commit SHA and target branch/tag.

## 2. Pre-Deploy Verification

Run in the workspace root:

```powershell
npm --workspace @game-game/api run lint
cmd /c npm --workspace @game-game/api run build
cmd /c npm --workspace @game-game/web run build
npm --workspace @game-game/web run lint
```

Notes:

- On this Windows environment `web lint` may need to be run after `next build`, because `.next/types` are generated by the build step.
- If `release-check.cmd` is used, prefer CI/Linux as the source of truth when Windows host process behavior is unstable.

## 3. Database And Storage Readiness

- Run migrations:

```powershell
npx prisma migrate deploy
```

- Verify `/api/health/details`.
- Verify storage is reachable:
  - `local`: uploads directory writable
  - `s3`: bucket reachable and public URL correct
- Verify auth origin policy against the actual web host that will be used for smoke and release.
- Verify backup scripts:
  - PostgreSQL backup path
  - media backup path

## 4. Live Smoke

With API and web already running:

```powershell
npm run smoke:mvp
```

Expected smoke coverage:

- web reachability
- API health
- `x-request-id`
- admin login
- trainer login
- media upload
- admin audit visibility
- commercial overview/history
- organization onboarding
- invite preview when pending invites exist
- child join/select/progress
- hint open
- help request and resolve
- mission completion
- trainer review flow
- media library quota/orphan summary
- template performance visibility

## 5. Manual Regression Pass

Verify these routes manually:

- `/`
- `/join/{joinCode}`
- `/participant/{participantId}/jams`
- `/mission/{participantId}`
- `/trainer`
- `/trainer/sessions/{id}`
- `/admin`
- `/admin/jams/{id}`
- `/admin/organizations/{id}/onboarding`
- `/invite/{token}`
- `/status`
- `/account`

Regression checks:

- child resume/history flow
- trainer live updates without refresh
- help queue and reviewed flow
- admin publish workflow
- media preview and orphan cleanup
- template creation flow
- support mode enter/exit
- organization branding on join/status surfaces

## 6. Fix And Re-Run

- Fix any regression found in smoke or manual pass.
- Re-run:
  - failed build/lint steps
  - `npm run smoke:mvp`
  - affected manual routes

Do not freeze the release until smoke and the impacted manual checks are green.

## 7. Freeze Release

Record:

- commit SHA
- migration version applied
- storage mode (`local` or `s3`)
- smoke timestamp
- backup timestamp
- known limitations

Recommended release note:

- deployed version
- database migration version
- storage provider
- smoke result
- rollback command/runbook link
